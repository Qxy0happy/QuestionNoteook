# 复习参数只露两个旋钮：间隔模糊 + 考试日期

FSRS 本身有 21 个权重、一个期望保留率、一个最大间隔、一个模糊开关。设置页**只暴露两个**：间隔模糊的开关，和**考试日期**。其余一律用官方默认（ADR-0002 钉的向量）。

用户填了考试日期之后，`MaximumInterval` 就取「距考试还有几天」——每次算调度参数时**现推**，不是在启动时算好烘进调度器（否则过了午夜它就旧了一天）。考试日期为空、或者已经过去，就退回库默认的 36500 天。保留率保持 0.9 不动。

用户原话是「间隔时间太长了。现在还剩 94 天」，然后提议「要不加个能够手动调整参数的设置细分项」。他选中的正是这两项 —— 这是自洽的：**有了考试日期这个硬边界，保留率就是一个多余的旋钮**。

保存设置时把库里**已经排出去**的到期日拉回上限之内（只动 `due_at`，不动 `stability` / `difficulty`：提前复习是 FSRS 允许的，而改后两者等于伪造这个人的记忆强度）。用户选的是「保存时拉回来」，不是「只对新评级生效」—— 后者会让那些已排到 196 天后的题在这 94 天里**再也不出现**。

拉回来是**单向**的：上限放宽（考试日期往后改、或者清掉）时，已经拉近的到期日不会自己弹回去 —— 那一步要用到的信息在拉的时候就已经没了。这一点写在设置页那行字里。

## 上限是**硬的**，而这要我们自己收口

官方库的 `MaximumInterval` 是**软的**。它先把每一档夹到上限，再为了保住 Again < Hard < Good < Easy 的严格次序往上加。实测（上限 94 天、复习过三次的卡）：

```
Hard 94 / Good 95 / Easy 96
```

也就是说「任何评级都不会排到上限之外」这句话库本身给不了，它能超出上限两天。而本决定要的正是那句话 —— 上限是**从考试日期推出来的**，超出两天就是考后两天。

所以评级的最后一步由我们自己收（`review.clampToCap`），收的只是**排出去的日期**（`Due` 与 `ScheduledDays`），`stability` / `difficulty` 仍是库算的原值。设置页那个四档预览走**同一个收口** —— 否则预览会显示 95/96 天而真去做是 94 天，一个说一套做一套的预览比不做预览还糟。

## 被否掉的做法

- **暴露那 21 个权重**：它们是拟合出来的向量，调了没人说得清后果。
- **暴露期望保留率**：调节它确实能缩短间隔，但那是「我想要多高的记住概率」的间接表达；而这个应用真正要说的是一句更硬的话 —— 「考试之前都得再过一遍」。保留率说不清考试那天在哪。
- **上限做成手填天数**：要用户在考试临近时自己回去改小，改晚了就晚了；而且「填多少」本身就是他答不上来的问题。
- **拉回来时把到期日铺开**（工作量均衡）：那需要把一批题按天重新分配，是另一张票的事。今天只做「拉进上限」。
