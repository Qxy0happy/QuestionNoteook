# 14: VLM 推荐每日复习量

**What to build:** 复习页显示今天建议做几道。推荐来自 VLM，它能看到「今日到期多少」与「最近的表现」。

这一层**在 FSRS 之上**再加一道闸：FSRS 自己用 `RequestRetention` 控制到期量，它只回答「今天最多做几道」。

**Blocked by:** 08（复习）、09（VLM 客户端）

**Status:** ready-for-human —— Go 侧 9 条测试全过（含做过变异检查的那条）；界面接线完成、`svelte-check` 0 错；**真机与真实网络都未验**

- [x] 推荐基于今日到期数量 + 最近表现
- [x] 显示在复习页
- [x] 用户可以不采纳
- [x] 它**不改变** FSRS 自己算出的到期时间
- [x] 测试用假 provider；断言推荐值被拒绝时队列行为回落到纯 FSRS

## Comments

### 「它不改变到期时间」不是承诺，是**没有写语句**

`internal/workload` 里一条写语句都没有 —— 它只调 `review.Queue()` 看一眼、给出一个数。
到期时刻与 `review_states` / `review_logs` 全程不被触碰，「闸」只是复习页内存里的一个计数。

**验收那条测试做过变异检查**：临时在 `Recommend` 里插一次 `review.Grade(...)`，
`TestNotTakingTheRecommendationFallsBackToPlainFSRS` 的四条断言全部报错（队列变了、题消失了、
状态与记录各多一行），改回后全绿。也就是说那条断言**绑在代码上，不是空转的**。

### 「最近表现」用了哪些数据，以及**没**用什么

只用 `review_logs` 真实记着的三列（`rating` / `reviewed_at` / `question_id`），滚动窗口默认 7 天，
汇总成：复习了几次（总次数 + 四档分布）、其中几天动过、涉及几道不同的题。每一样都是那三列的直接聚合，
**没有一步是反推**。

- 窗口取**滚动 7×24h** 而不是「最近 7 个自然日」是刻意的：自然日要引入「今天是哪一天」，
  而那个判定在 `internal/review` 只有一处（`endOfToday`）。在这儿另定一个「一天从几点开始」
  就是第二份定义，迟早走偏。
- **没用** `scheduled_days` / `stability` / `difficulty`：那些是 FSRS 当时的输出，说的是「这道题被排到了多远」，
  不是「他表现得怎么样」。取平均得不出比四档分布更说明问题的东西 —— 不往里塞，不做「现编」。

**真正缺的一块，照实说**：数据里**没有**「上次推荐了多少、他采纳没有」—— 推荐不落库（它本来就不该改数据），
所以模型看不到「我上次说做 10 道，他做完没有」。这是这一票唯一真正缺的东西。
另外「每次复习花了多久」应用里根本没有这个计时，给不出。

### 「今天再做几道」的口径，以及它的后果

`Due` 是**此刻队列里还剩多少道**，不是「今天零点时到期多少」。所以用户做了 15 道之后重进这一页，
会拿到新的一条「再做 N 道」（基于当时的剩余量）—— **不叠加、也不去重**。

这是有意的：评过的题被推到明天之后，队列长度本身就等于「今天还剩多少」。
若想要「今天总共做 N 道」的口径，得加「今日已做」这一项，而那要引入本地零点 ——
也就是**第二份「今天」的定义**（见上）。所以先不引入。

### 失败一律静默退化

没配 VLM、断网、模型答得不能用（`ErrUnusableAnswer`），在页面上是同一件事：**这一条不出现**。
队列、评级、FSRS 那一条链一点不受影响。所以刻意**不写** `listError` —— 那个位置留给「复习本身坏了」，
把推荐的问题混进去会让用户以为复习不能用了。推荐是锦上添花，不能变成单点故障。

队列空的时候**不打网络**（`Suggest == 0`，不是错误）。

### 命名与文档

包名叫 `workload` 而不是 `plan`：spec 的正文用的是「每日复习量」，而 CONTEXT.md 里原先没有这个词。
**已往 CONTEXT.md 补上「复习量 (Workload)」**（接线时补的），并把 `plan` 列进了 _Avoid_。

### 未验证

- **真实 VLM 一次都没调过**：提示词是**暂定**的（与打标签、讨论那两处同一个处境）。
  它给不给合规 JSON、给的数合不合理，第一次真跑才知道。改措辞只动 `internal/workload/prompt.go`
  那一个常量（**没留配置覆盖口子** —— 打标签那处留口子是因票 01，这里连一次都没跑过，
  先不给没人调过的旋钮）。
- **闸是手验项**：`cap/done/remaining` 在 `Review.svelte` 里，按 spec「前端是薄视图」没有自动化覆盖。
  真机要走的：采纳 → 做到量 → 收工屏 →「继续做完」→ 再做；以及不采纳时整条推荐条消失、
  队列与以前逐字相同。Go 侧能自动断言的那一半（推荐不写库、不动队列、不改 FSRS 结果）已经测了。
- **每次切到复习页都会问一次模型**（一次 IPC + 一次 API 调用），采纳过之后当天不再问。没做缓存/节流。
- 两条全表扫没在真实数据量上量过（`review_logs` 按 `reviewed_at` 过滤走不上 `(question_id, reviewed_at)`
  索引；`review_states` 整表读主键，为了避开 `IN (?,?,...)` 的参数上限）。数据量是个人错题本级别，
  注释里写明了。
