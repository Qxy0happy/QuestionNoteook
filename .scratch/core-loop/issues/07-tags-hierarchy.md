# 07: 标签：三层树 + 手工打标签 + 筛选

**What to build:** 建立**学科 > 章节 > 知识点**的三层**标签**；能给错题打标签；题库页能按标签筛。

**Blocked by:** 05（入库与题库列表）

**Status:** ready-for-human —— Go 侧测过（22 条），前端接线完成且 `svelte-check` 0 错；真机未验

- [x] 标签是自引用树，固定三层
- [x] 顶层学科由用户自由填写，只预置考研四门作为初始值
- [x] 能给一道错题挂**多个**标签
- [x] 题库页能按标签筛选
- [x] 删掉一个中间节点时，其子节点的处置有明确行为，且被测试覆盖
- [x] Go 侧测试覆盖树的增删改与按标签筛选

## Comments

### 层级是列，不是现算的

固定三层是这套模型的硬约束，所以 `level` 存进库里，schema 层就能拦住「知识点下面再挂一个」
（`CHECK (level BETWEEN 1 AND 3)` 加上 `CHECK ((parent_id IS NULL) = (level = 1))`）。
代价是 level 必须与 parent_id 一致 —— 那就**不提供「移动节点」**，一致性因此不会被破坏。

预置的四门（数学/英语/政治/专业课）写在**迁移里**，只在建库时发生一次：用户删掉某一门之后
它不会自己长回来。换成「启动时补齐」就会，那是错的。

### 删中间节点 = 级联删整棵子树

理由：三层是**语义**层级而不是纯粹的结构深度 —— 「章节」的含义是「学科下的一块」，
把子节点提上来等于让知识点冒充章节。反过来「没有章节的学科」是合法的中间状态，
所以级联不会产出不合法的树。返回值 `DeleteResult{DeletedTags, UntaggedQuestions}` 就是
为了让界面能把破坏性说清楚。行为由 `TestDeleteMiddleNodeCascades` 钉住。

### 筛选：点父标签自动带上子孙

`QuestionsByTags(ids)` 是**并集**且含子孙，空数组 = 不筛 = 全部错题 —— 所以「筛」与「不筛」
是同一个调用，前端不必分两条路。

### 前端接线（本次补上）

- 列表页顶栏「筛选」开 `TagFilter`；下面一格「新建学科」是**顶层学科由用户填写**的入口
  （章节与知识点由识别那边建，不在本票范围内）。
- 详情页「标签」开同一个组件，`onSelect` 里整体替换那道题的标签；勾选先上屏，写库失败
  就把这道题真实的标签读回来，**不让界面停在假的勾选状态上**。

### 题库页改成「学科页签 + 左侧细分树」（2026-09-16 用户提的）

用户原话：「题库查看分成两个标签页，默认进入未打标签的内容，再就是按照学科标签成为标签页与未打标签同级。
细分标签使用树分类在左侧出现。」

- **页签**＝`未打标签` + 每一门顶层学科（顺序照 `Tags.List()`），默认停在**未打标签**；
  末尾一个 `＋` ＝原来那个「新建学科」入口（**永远建顶层学科**，即使当前正停在某门学科里）。
- **选中学科后**左侧出现**那门学科**的章节 / 知识点树；`未打标签` 那一页**没有左栏**（没有标签可筛）。
- **复用 `TagFilter`**，只给它加了两条可选 prop（`title` / `fill`，默认值保证另外两处用法**一字不变**）。
  没重写一棵树：勾选、半选、连子孙一起勾（`collect()`）那三条逻辑都在它里面，抄一遍就是三处会走样的地方。
- **筛选集合 = `[学科ID, ...左侧树勾中的]`**：学科**始终**在里面（页签本身就是「这一页只看这门学科」），
  树是在它之上再收窄 —— 勾中的本来就在这门学科下，并集等于收窄。
- 列表顶栏的「筛选」按钮与那块面板**整块删掉**了（`showFilter` 状态也删了）；
  `TagFilter` **留着**给详情页打标签用，那一处的用法没动。

**左栏宽度**：`clamp(8rem, 36vw, 11rem)`。这是**按字符宽度算出来**的，不是拍的：
一行要装「时间 ≈96px + 间距 12px + `AnswerBadge` ≈51px + 行内边距 32px + 列表内边距 24px ≈ 215px」，
而 393px 竖屏上树占 141px、列表剩 **251px**，360px 老机剩 **229px** —— 都够。
两头收口的理由：再窄下去知识点那层只剩两个字、点不准；宽屏上再宽也没用，列表那边还要放图。

**Go 侧新查询**：`UntaggedQuestions()`。空数组对 `QuestionsByTags` 是**全部**（不筛），
不是「没有标签」，所以这条得单独写：

```sql
SELECT … FROM questions q
WHERE NOT EXISTS (SELECT 1 FROM question_tags qt WHERE qt.question_id = q.id)
```

用 `NOT EXISTS` 而不是 `LEFT JOIN … IS NULL`（那个要 `DISTINCT` 兜底、排序还会被关联行数搅乱），
也不用 `NOT IN`（碰上 NULL 会整条查询不出结果）。排序与别的列表查询一致。
它落在 `internal/tags` 而不是 `library`：「没有关联行」是**关联表**的属性。**不加迁移、没动 schema。**

**空态话术分了三档**（未打标签页空 / 学科页空 / 学科页且树里勾了东西才空）：默认页签变成
「未打标签」之后，新用户第一次进来最容易看到的就是第一档，那里得说清「拍一道、打上标签才归到学科页」，
而不是一句让他不知道该干什么的「没有错题」。

⚠️ 宽度与「装不装得下」**是按字符宽度算的，没在真机上量过**。

**左栏可以拖宽了**（用户 2026-09-16：「这个分类树展示的界面太小了，我希望能加上一个分界拖动条」）：
两栏之间一条分界条，拖它改左栏宽度，**双击复位**。三件事少一件都会坏 ——
**指针捕获**（手指滑出那条窄条甚至滑出屏幕，move 照样回得来）、CSS 上的 **`touch-action: none`**
（不给的话这根手指的横滑会被**外层翻页手势**抢走，变成翻到题库/复习页；与应用里选框的四个角柄
同一个道理）、以及 `preventDefault`。命中区 10px、只画 1px 的线，并用负外边距**骑在**边线上
（否则它自己会额外占 10px 把列表挤窄）。

宽度**默认仍交给 CSS 那个 `clamp`**（跟着屏宽走），**只有用户亲手拖过之后**才钉成像素并写进
`localStorage` —— 那之后就该听他的，不再跟着 vw 走；存的是这个 WebView 的存储，所以**重启在、
卸载没**。边界：左栏最窄 8rem、列表至少留 7rem。

### 明确没做的（不在验收项里）

标签的**建/改名/删 UI** 只覆盖了「新建顶层学科」：重命名、删除、以及手工建章节/知识点
都没有界面。Go 侧 `Create` / `Rename` / `Delete` 都在，缺的只是入口 —— 识别（票 09）会直接
调它们。另外列表行上**没显示每道题挂了什么标签**（`TagsOfQuestions` 已备好，但没有验收项要它）。
