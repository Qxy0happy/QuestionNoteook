# 10: 讨论

**What to build:** 复习一道错题时能就它提问。入口是几个**预设追问**，之后可以继续**自由聊**。**讨论**记录挂在错题上，下次回来看得到。

**Blocked by:** 08（复习）、09（VLM 客户端）

**Status:** ready-for-human —— Go 侧 16 条测试全过（含"两轮问答只上传一次图"），接线完成、`svelte-check` 0 错；**真实网络与真机都未验**

- [x] 预设之后可以继续自由输入
- [x] 对话记录挂在错题上，重新进入这道题时能看到
- [x] 讨论复用同一个 provider 抽象

## Comments

### 用户的字**先落库**，再调模型

顺序是 `append(用户那句)` → `读整段历史` → `asker.Ask()` → `append(模型那句)`。
这样网络断掉、没配 VLM、模型返回空文本这几种失败下，**用户打的字都还在**——
失败时前端重读一次历史，屏幕上就是一条没人应答的提问，可以再问一次。

反过来（先拿到回答再一起写）在失败时会把用户刚打的字一起丢掉，那是这张票最不该有的失败方式。

### 排序：同毫秒靠自增主键兜底

`ORDER BY created_at, id`。毫秒精度**不够用**——用户那句与模型那句通常落在同一毫秒里
（中间只隔一次网络往返），只按 `created_at` 排的话，同话题的两句谁先谁后由 SQLite 决定，
对话会随机出现「回答在提问之前」。

兜底是自增主键，所以 `id` 必须是 `AUTOINCREMENT` 而不是裸 `INTEGER PRIMARY KEY`：
裸 rowid 会复用被删掉的最大值，删掉最后一句再问一句就可能拿到更小的 id，兜底就失效了。
`TestHistoryOrdersSameMillisecondByID` 用钉死的时钟让四行共享同一个时间戳，钉住这条。

### 图与多轮：接缝开在 `internal/vlm`，不在讨论包里

讨论每一轮都要带**题图**（和答案图，如果有），而「同一张图只上传一次」的那份
hash → file_id 缓存、以及取配置 / 选 provider / 读图，全在 `internal/vlm` 里。
所以在 `internal/vlm/discuss.go` 开了一个接缝：

```go
func (s *Service) Ask(questionID int64, history []Message) (Reply, error)
```

讨论只依赖它（`discussion.Asker` 接口，`*vlm.Service` 结构上直接满足，接线不需要适配壳）。
接缝开在讨论包的话，要么把取配置 / 拼报文 / 回落内联那套抄成两份（迟早走偏），
要么把缓存暴露出去（漏封装）。

图挂在**最后一条 user 消息**上（复制一份再挂，不就地改调用方的切片）：
一次请求只带一份、不随轮数翻倍，且挨着这次的问题——将来做历史截断也不会因为
「开头那条被丢掉」而把图弄丢。代价是**每轮都重发一次图**，换来模型每轮都真的看着图在答。

**这条有测试**：两轮 `Ask` 加一次 `SuggestTags` 之后 `fake.UploadCount() == 1` ——
证明缓存真的共用了，不是纸面承诺。

### schema（迁移 4）

`discussions`：一行 = 讨论里的一句话，**不另建会话表**。每道题只有一条会话，
所以 `question_id` 本身就是会话的身份；再来一张 `conversations` 表只会多一个必须恒为 1:1 的外键。
列名用 CONTEXT.md 的词：`question_id` / `role` / `text` / `created_at`。
`role` 的取值就是 `vlm.Role` 的那两个字符串，编译期绑定，两个包不可能漂移。
外键级联到 `questions(id)`：题没了讨论跟着走。

### 预设追问放在 Go 侧

三条预设**不是装饰，是讨论里的第一条记录**——按下去等于替用户写了一句话，那句话会入库、
会进请求报文。所以「按的是什么」与「记的是什么」必须同一份字符，只能有一个来源；
写在前端就会出现「按钮写着 A、库里存着 B」。而且「至少三条且含点名的这三条」是验收条款，
放 Go 侧才守得住（前端按 spec 不做自动化测试）。

没留配置覆盖口子（与打标签的 prompt 不同）：那条留口子是因为票 01 还没定论，
这条路径连一次真实问答都还没跑过，先不给一个没人调过的旋钮。

### 明确没做

- **流式输出**：票据没要求。`Provider.Chat` 是一次性返回，接口里也没有 stream 的位置，
  所以界面上是「正在想…」而不是逐字蹦。要做先得动 `Provider` 抽象。
- **历史截断**：每轮把整段对话原样发出去。代价是长对话会把上下文吃光，超了就是一次服务方报错。
  要截断改 `wireHistory` 一处（保留最后 N 轮 + 在头一条前面加说明）。
- **删除 / 重试某一条**：模型返回空白时用户那句会留在库里且没人应答，可以再问一次，
  但没有「删掉这句」的入口。那是后续票的事。

### 两处越界的测试改动（已确认接受）

`internal/review/service_test.go`（+4）与 `internal/tags/service_test.go`（+1）的
`TestUpgradeFromOlderSchema`：各自的「回退到老库」DROP 列表里加了一行 `DROP TABLE discussions`。

这两个测试的套路是「建当前模式的库 → 只删自己那条迁移的表 → 退回 user_version → 重开看迁移重跑」，
所以**每加一条迁移都要同步补一行**（`internal/tags` 里那段注释原话就是这么写的）。
不改的话两个包各红一个用例（`table discussions already exists`）。
把迁移改成 `CREATE TABLE IF NOT EXISTS` 能让测试变绿，但那是**为了让测试通过而削弱迁移的保证**，
本末倒置，已否掉。

### 一处已知的多余面

`vlm.Service.Ask` 是导出方法，Wails 把它也生成到了前端绑定上
（`frontend/bindings/questionbook/internal/vlm/service.ts` 里能看到）。
功能上无害——记库的是讨论服务，绕过它去调只会得到一次不落库的问答——但它是多出来的面。
要收掉得看 Wails 有没有排除单个方法的办法，本票没做。

### 渲染：markdown + KaTeX（接线时补的，票据原先完全没提）

**这是 spec 阶段的一个缺口，不是"没要求所以没做"。** 票据只写了「继续自由聊」，没写模型吐回来的字怎么显示。
后果很具体：模型回答数学题几乎必然带 LaTeX，而 markdown 是这类模型默认的输出格式 ——
在补这个之前，讨论里看到的是 `$\frac{a}{b}$` 和 `**重点**` 的原样字符。

`frontend/src/Markdown.svelte`：marked + marked-katex-extension + KaTeX + DOMPurify。
**任何以后要显示模型文字的地方都该用它**（票 11 的待批准层就是下一处）。

几个不显然的点：

- **先 markdown、再消毒**，顺序不能反。marked 会原样放行输入里的 HTML（官方明确说消毒不是它的事），
  链接还能带 `javascript:`，而模型输出是**不可信**的 —— 题图里完全可能藏着让它输出 `<script>` 的文字，
  而这个 WebView 里有 JS 桥（能调到应用自己的服务）。所以进 `{@html}` 的每个字节都先过 DOMPurify。
- **`nonStandard: true`**：默认那档要求公式结尾的 `$` 后面跟空白或标点，而中文正文常常不写空格
  （`$x^2$的最小值`），公式会被当纯文本漏掉 —— 那正好是这个组件要解决的问题没解决。
- **`FORBID_TAGS` 里两条是实测出来的，不是照抄文档**（把整条链在 Node 里配 jsdom 真跑了一遍）：
  1. **DOMPurify 默认放行 `<style>` 元素** —— 实测 `<style>body{display:none}</style>` 原样活下来。
     样式是全局的，模型一句话就能把整个应用改样；更阴的是 CSS 能用属性选择器把值拼进 `url()`，
     一位一位读走 —— 而**设置页那个 API Key 输入框的 value 正好落在这个射程里**。禁元素。
     但行内 `style` **属性必须留着**（也实测过）：KaTeX 的间距与垂直对齐全靠它，禁掉公式就散架。
     这两件事同名不同物。
  2. 表单类（`form`/`input`/`button`…）默认也放行 —— `<form action="https://…">` 能把这个 WebView
     导到别的页面去伪装成应用。一并禁掉。
  3. 顺带：MathML 里的 `<annotation>`（TeX 原文）默认被当陌生标签摘掉，用 `ADD_TAGS` 补回来了 ——
     摘了不花屏，但读屏与「复制成 MathML」就没东西可用。
- 未解析成功的公式**不抛**（`throwOnError: false`）：模型偶尔吐半截 `\left(`，抛出去整条消息就没了；
  标红显示原文至少看得见。`trust: false` 禁掉 `\href` / `\htmlClass` 这类能带出 URL 或属性的命令。

**代价**：JS 包从 81.5 kB 涨到 **437 kB**（gzip 139 kB），KaTeX 还带进约 1.5 MB 字体
（`.woff` 与 `.ttf` 各产了一份）。都进了 APK。要瘦身可以在构建时只保留 woff2 并做子集化，本票没做。

### 用户报的三个毛病 + 两件新功能（2026-09-16 那一轮）

**1. 打字时输入框被键盘盖住。** 根因**不在 manifest**：`targetSdk 35`（安卓 15）强制边到边之后，
`windowSoftInputMode="adjustResize"` 对输入法**已经不生效**（窗口不再被压短），而 WebView 自己
也没有 OSK 感知 —— `visualViewport`、`dvh`、`interactive-widget` 在 WebView 里**都不动**
（crbug 40287394）。所以键盘高度只有一个可信来源：宿主报的 `common:keyboard` 事件
（开关在 `main.go` 里 `SetKeyboardWatch(true)`，默认是关的）。

⚠️ **这条连带修掉了另一个 agent 的聊天页**：它按「adjustResize 压矮 + visualViewport 兜底」写的，
而这两条在这个目标版本上**都是死的** —— 输入框照样会被盖住。已改成同一个事件。

两个容易错的细节：键盘高度是**物理像素**（要除以 devicePixelRatio）；抬的时候要**减掉
输入框底边到屏幕底边那一段**（底下那条导航栏本来就在那儿），否则输入框会浮在键盘上方空一截。

**2. 宽内容把气泡撑出屏幕。** 根因是 `.line` 是 column flex、`.bubble` 在交叉轴上按
`align-items: flex-start` 摆，宽度成了 **fit-content** —— 里面一旦有 `min-content` 大于可用宽度的
东西（不能折行的 `pre`、宽表格、KaTeX 的 display 盒子），气泡就比屏幕宽。`.md` 上那条
`overflow-wrap: anywhere` 只管得住**能折的文本**，管不住那三种。改在源头两处：
`.bubble { max-width: 100% }`，以及给 `table` 自己的滚动容器（`overflow` 对 `display: table`
的盒子不生效，必须先变 block）。**没有一处是 `overflow-x: hidden`。**

**3. 长按没有编辑 / 重发 / 复制 / 选择文本。** 选了**自绘菜单**，取舍：系统的长按菜单**加不了项**
（「编辑并重发」「重新生成」是应用自己的动作），而全局是禁选的（应用不是文档）。代价是
**单纯复制一小段比系统多一步**；补回来的是「选择文本」那一档 —— 按下去把那条 opt-in 成可选，
之后系统的手柄、放大镜与它自己的复制菜单都归系统管（不自己实现选字）。

**4. 编辑并重发 / 重新生成**（Go 侧新增，**不加迁移**）：
- `Regenerate(questionID, messageID)`：**先问、后换**。只认「最后一条且是模型回答」，
  否则 `ErrRegeneratable` —— 重说中间那条要顺手丢掉后面几轮，那是用户没要求过的删除。
  **失败时库里一个字节没动**（有测试）。
- `EditAndResend(questionID, messageID, text)`：顺序与 `Ask` 一样，只是「记下用户这句」变成
  「换掉用户这句」，`replaceFrom` 在**一个事务**里删掉这条及之后、写下新字 —— **先落库、再问模型**。
  所以模型失败时用户刚打的字**在库里**（有测试直接读库断言）。
- 边界用 `id >= X` 而不是下标（AUTOINCREMENT 保证「X 及之后」），且 `question_id` 那个条件
  一个字都不能少，否则会删到别的题。

**5. 公式渲染不对。** 根因：模型吐的是 **`\[ ... \]`**，而 `marked-katex-extension` **只认 `$`** ——
所以那些公式被当纯文本原样显示。（这一条是拉下设备上的讨论记录、看了真实输出才定的，不是猜的。）

修法**两处都做**：渲染链在进词法层之前把老写法归一成 `$`/`$$`（`Markdown.svelte` 的
`hooks.preprocess`），提示词里也要求用 `$`/`$$`。

⚠️ **一个不显然的坑**：光把 `\[` 换成多行 `$$` 是不够的 —— 实测（marked 18 + 该扩展）**多行 `$$`
紧跟正文、中间没有空行时根本不认它是块级**，段落不会在 `$$` 处断开，整段变纯文本。
所以归一的时候把公式**并成一行** `$$ 正文 $$`（单行走行内规则那条路，在正文里、自己一行、
列表项里都成立）—— 一条规则覆盖所有位置，比「看缩进、补空行」可靠。**升级 marked 或那个扩展
之后要重跑一次这条链**（形状判断是实测出来的，不是文档保证的）。

**6. 思维链（用户要的，默认收起）。** `discussion.Message.Reasoning` 与 `agent.Answer.Reasoning`
把它带到界面，每条回答下面一个原生的 `<details>`（无 `open` = 默认收起），里面照常走 markdown
渲染（所以思考过程里的公式也渲染）。**不落库**：它是当轮的东西，存下来只会让库翻倍，
而用户的原意是「别让人以为死掉了」。

agent 那条路是**多轮工具调用**，每轮的 assistant 消息都自带一段思维链 —— 按轮次先后接起来、
中间空一行（前面几段是它决定要查什么时想的，最后一段才是得出这个回答的那一段）。

**「思考强度设为 high」不用改代码**：对着官方文档核过，思考模式**默认开启、强度默认就是 `high`**
（[Thinking Mode](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode)）。加了只是多一个
可能被 400 拒掉的旋钮。
