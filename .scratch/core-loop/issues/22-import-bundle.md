## 为什么现在做

GitHub Releases 成了分发平台（2026-09-17），更新方式是覆盖安装，而安卓只允许**同一把钥匙**签的包覆盖安装。手机上现有那份 debug 包与发行版签名不同，切换到发行版必须卸载重装 —— 卸载清空整个错题库。所以先把导入补上：补完之后，任何重装 / 换手机 / 换钥匙，最坏也只是「导出 → 重装 → 导入」，而不是清库。

## 决定

### 跨一次重启，而不是当场换

正式数据被一条已经打开的 SQLite 连接与一个图片目录攥着，而 library / tags / review / discussion / workload / digest 都注册在 Wails 上、各自握着那条连接的引用。当场换等于把整张服务图重建一遍 —— 那就是把「重启应用」用代码再实现一次。所以 Go 只把包**解好摆着**（`<数据根>/import-pending/`，`Commit` 之前不写就绪标记），等下次启动、库还没打开的那一刻换（`importer.ApplyPending`，在 `library.Open` 之前）。

### 零 Java 改动

Wails 运行时自带文档选择器：`app.Dialog.OpenFile()` 在安卓上走 ACTION_OPEN_DOCUMENT，选中的文件被宿主导进应用私有目录，Go 拿到的是**真实文件系统路径**（`dialogs_android.go` → `MainActivity.launchFilePicker` → `copyUriToCache`）。导出那边要自己写 Java，是因为 MediaStore 的**写**没有对应的 Wails API；**读**有。

### 整体替换，不是合并

库里的错题 id 是每台设备自增的，跨设备没有稳定身份；「合并」得先定义同一条错题是什么，那是另一个问题。用户故事 44 要的是「搬过去」，不是「并起来」。

### 包里带上两份设置（不带凭据）

`review.json`（间隔模糊、考试日期、保留率）与 `digest.json`（提醒钟点）跟着包走，换手机不用重填。`vlm.json` **刻意不带**：它带 API key，而包会落到「下载」目录，那儿别的应用读得到。这改动了票 13 定死的包布局，所以导出那一侧也动了（`export.WithBundleExtras` + `export.SettingsNames`）。

### 被否掉的

- **导入前自动先导出一份当前库**：看着稳妥，但把导入这一步系在 MediaStore 写入成功上（安卓 10 以下那条路本来就是坏的）。撤回靠改名留 bak，不依赖宿主。
- **让 Go 侧当场重启应用**：要新加 Java，而且「重启」在安卓上不是个干净动作（进程可能被杀、Activity 可能被复用）。
- **只认「库与图」的包**：那样换手机还得重填考试日期 —— 而考试日期正是 FSRS 上限的来源。

## 没验的

- **真机**：挑文件那一段（点按钮弹不弹系统选择器、能不能读到「下载」里的 zip、取消是否干净退出）。Go 侧的往返与每一条拒绝路径都有测试，但这一步只能真机看。
- **中途失败的回滚**：`apply.go` 里那几处 `rollback` 没有测试钉 —— 要触发它得让某一步 `os.Rename` 失败，而这套流程里每个目标都在前一步让开了，构造不出可移植的失败点。这件事写在 `apply_test.go` 的文件头里，没有假装测过。
- **大库的耗时**：解包时会逐张解码图片、核对内容与文件名是否相符（导出那边不核，导入面对的是应用之外的文件，核一遍才闭合）。几百张图在手机上的耗时没量过 —— 如果慢到不能忍，这是第一个该放宽的地方。
