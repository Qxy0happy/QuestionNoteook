## Comments

用户原话：「这个图片作为App的icon」，给的是一张 AI Studio 生成的**预览图**
（1408×768 的浅灰底 + 中间一张白色圆角卡片 + 投影）。

⚠️ 那张图给的是 `blob:https://aistudio.google.com/...`，**取不到** —— `blob:` 是浏览器那个
标签页内存里的引用，外面的工具按它取不到字节（何况 aistudio 要登录）。真要文件：另存为到
磁盘再给路径。

### 那张图是「预览图」，不是图标

真正的图标是中间那张白色卡片，外面还垫着浅灰底和一圈投影。所以不能整张缩过去（缩完是一张
小卡片配一大圈灰边），得先找到卡片的边界再裁。

**找边界走了两条弯路，都记下来**（都在 `tmp/iconmake` 那个一次性工具里，未进版本库）：

1. **「有近白像素就算进来」的外接框不行**：底上的 JPEG 噪点总有几颗越过 250 的线，一颗就把
   框撑到整幅图（量出 1407×643，那正是整个宽度）。
2. **按行/列占比取阈值也不行**：卡片中间那一大块是彩色的书，穿过书的那些列里白色只剩上下两条
   窄边 —— 按 20% 占比算，只有卡片左右两边那点空白列能被选中（量出 157 列宽，那是左边距）。

最后用的是：**每行/每列有几颗近白像素就算数（阈值 5），然后取最长的一段连续**。卡片覆盖到的
行和列都是连续几百个，而噪点凑不出连续几百个。量出来：

```
白色行 125..644（520 行，该段最少 83 颗/行）
白色列 442..965（524 列，该段最少 193 颗/列）
卡片外接框 524 x 520   →  裁成 516 x 516（短边居中，各让掉 4 / 2 px）
```

「该段最少 83 颗/行」这个数是用来看出**这一段有没有掺噪点**的 —— 掺了的话最小值会贴着阈值 5。

裁的时候取**短边**并按中心居中，不假设外框恰好正方（边缘总有几像素的锯齿）。

### 圆内接正方形：圆那张不能只切一刀

第一版圆图标把**书的外轮廓削平了** —— 书的上下两条边正好落在圆外那圈里。所以圆里**先铺一层
白**，内容缩到 **88%** 居中再贴：露出来的那一圈是白的而不是透明的（否则图标边上会缺一块），
而「白铺白」接缝看不出来。88% 是看着定的：再大三五个百分点，书的轮廓就贴上圆周了。

内容自己那圈圆角也要切掉 —— 裁出来的那块四角是预览图的浅灰底（卡片是圆角的，框是方的）。
圆角半径**取小不取大**（20%，卡片看上去是 22%）：取小了只是少一点白，取大了会把灰底露出来
一条，两者里只有后者看得出来。

### 其它

- **纯 stdlib 的小工具**，没往项目里加依赖：缩小用面积平均（box filter，一次缩 7 倍以上时比
  双线性干净），圆角与圆形用 4×4 超采样做遮罩（所以边缘是抗锯齿的）。
- **没做 Android 8+ 的自适应图标**（前景/背景两层）。那套要求把图形放进 66% 的安全区，而
  「安全区到底留多少」正是纸上推不准、得看真机的东西（这台机器上我在这类事情上错过两次）。
  现在走的是旧式图标那条路（`@mipmap/ic_launcher` + `roundIcon`），与清单里原本的写法一致。
  要换自适应图标是另一张票。
- 顺带发现：`jniLibs/x86_64/libwails.so` 是 9-15 的陈旧遗留，被塞进每一个 debug APK（14.57 MB，
  占那个 32 MB 包的 45%）。不影响功能（手机只加载 arm64），但那 14 MB 每次装机都白传。
