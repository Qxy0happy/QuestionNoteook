# 13: 整库导出

**What to build:** 一键把整个错题本导出成一个 zip，里面是数据库与图片（**导出包**）。沙箱意味着卸载即全没，这是防丢的唯一手段。

**Blocked by:** 05（入库与题库列表）

**Status:** ready-for-agent —— 落点已定，但**分两步做**（见 Comments）

- [ ] 导出的 zip 里，库与图片都在
- [ ] 库里引用的**每一张**图都能在 zip 里找到
- [ ] zip 里**没有**库未引用的孤儿图片
- [ ] 上面两条都有测试，且双向断言
- [ ] 沙箱限制下能落盘，并明确告知用户落点

## Comments

### 落点定了：**系统「下载」目录**（2026-09-16，用户定）

这一条必须先定，因为它决定要不要动 Java 宿主。

根子在这张票自己的目的上：「**卸载即全没**，所以导出是防丢的唯一手段」。那就意味着导出**不能**
落在应用私有目录里 —— 包括 `getExternalFilesDir()`，它同样跟着卸载一起没。要落到外面，
WebView 与 Go 都碰不到 Android 的存储 API（scoped storage 下直接写 `/sdcard/Download/` 会被拒），
**必须补一段 Java 宿主代码走 MediaStore**。

另一条路是「导出后直接弹系统分享面板」（`ACTION_SEND`），同样要补宿主，但不用管文件落在哪。
用户选了下载目录 —— 文件在系统「文件」App 里能直接看到，「明确告知用户落点」这条也才说得清楚。

### 分两步做（用户定）

1. **先做打包逻辑**：把库与图打成一个 zip，把「库引用的每一张都在 zip 里」「zip 里没有孤儿」
   这两条**双向断言**的测试做出来。落盘那一层留一个接口（往哪儿写由调用方给）。
2. **落盘缓一步**：MediaStore 那段宿主补丁等手头这批票落地后再做 —— 它需要真机反复试，
   而且要改 `MainActivity.java`（那份是脚手架补丁，升级 Wails 会丢，得记着）。

先做第 1 步的理由：打包逻辑是纯的、可测的，而且它把「导出包里到底该有什么」这件事定死了 ——
宿主那段只是把已经确定的字节写到某个目录，不该和它混在一起想。

### 做第 1 步时要留意的两件事

- **WAL**：库开了 `journal_mode=WAL`，`library.db` 之外还有 `-wal` / `-shm`。
  直接复制 `library.db` 会**丢掉最近写入**。导出前要么 checkpoint，要么用 SQLite 的备份接口。
- **图片是按内容寻址的**（SHA-256，ADR-0004），而**同一个 hash 可以被多道题引用**
  （既可能是 A 的题图、又可能是 B 的答案图），所以「zip 里没有孤儿」这条断言不能按题去重，
  得按**库里的 hash 集合**去重 —— 去重发生在文件那一层，不是错题那一层。
