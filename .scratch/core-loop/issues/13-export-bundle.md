# 13: 整库导出

**What to build:** 一键把整个错题本导出成一个 zip，里面是数据库与图片（**导出包**）。沙箱意味着卸载即全没，这是防丢的唯一手段。

- [x] 库里引用的**每一张**图都能在 zip 里找到
- [x] zip 里**没有**库未引用的孤儿图片
- [x] 上面两条都有测试，且双向断言

## Comments

### 落点定了：**系统「下载」目录**（2026-09-16，用户定）

这一条必须先定，因为它决定要不要动 Java 宿主。

根子在这张票自己的目的上：「**卸载即全没**，所以导出是防丢的唯一手段」。那就意味着导出**不能**
落在应用私有目录里 —— 包括 `getExternalFilesDir()`，它同样跟着卸载一起没。要落到外面，
WebView 与 Go 都碰不到 Android 的存储 API（scoped storage 下直接写 `/sdcard/Download/` 会被拒），
**必须补一段 Java 宿主代码走 MediaStore**。

另一条路是「导出后直接弹系统分享面板」（`ACTION_SEND`），同样要补宿主，但不用管文件落在哪。
用户选了下载目录 —— 文件在系统「文件」App 里能直接看到，「明确告知用户落点」这条也才说得清楚。

### 第 1 步做完了：`internal/export`（打包逻辑）

```
library.db          库
cards/<hash>.png    库里引用到的每一张图，按内容 hash 命名
```

这两条路径**刻意与私有目录下的布局同名** —— 解包回去就是同一份。

**WAL 用 `VACUUM INTO`，不是 checkpoint + 拷文件。** 理由：VACUUM INTO 按连接当前看到的
已提交内容生成一份**自洽的单文件库**，含还在 `-wal` 里的提交、不含旁挂文件、顺手整理碎片，
而且是一条语句，没有「checkpoint 与拷贝之间那个窗口」（那期间的写入要么进不了包，
要么让拷到一半的文件成为撕裂镜像）。把 `-wal`/`-shm` 塞进 zip 也不对：解包侧拿到过期的
旁挂文件会恢复出一个错的库。

**这条有牙齿，不是纸面承诺**：`TestNaiveCopyOfDBFileLosesRecentWrite` 按票里点名的错误做法
直接拷主库文件，断言那份拷贝**读不出**刚写的题（实测：能打开，但 `GetQuestion` 报错）。
所以 `TestWriteBundleSeesJustWrittenQuestion`（写一道题、**全程不关库**、立刻导出、只把包里
那份 `library.db` 解到干净目录再读回）不是碰巧 checkpoint 过了才通过。

顺带一个跑出来的事实：**VACUUM INTO 会把 `PRAGMA user_version` 带过来**。若它丢了，
`library.Open` 会从头重跑迁移、撞上已存在的表而报错 —— 测试里只要库打得开就说明没丢。

**「孤儿」的判据是「库里的 hash 集合」**，不是按题去重（ADR-0004：同一个 hash 完全可能既是
A 的题图、又是 B 的答案图）。题图列与答案图列都算，空串跳过（那是「还没拍答案」的占位）。
三条独立测试：有引用的都在（带 `len(refs) != 5` 的护栏，防止断言在空集合上空转）、
盘上没有引用的残留图进不了包、共用 hash 只出现一次且没被判成孤儿。

**契约是「要么一个完整的包，要么什么都不写」**：缺图在写第一个字节**之前**就被核出来
（对每个 hash `os.Stat` 并确认是普通文件），返回 `ErrImageMissing`、`Result` 为零值、
`w` 上零字节。其他失败（磁盘写满）会留半截 zip，所以调用方该先写临时文件、成功了再改名。
库用 Deflate、图片用 `zip.Store`（PNG 已压过，手机上再压一遍是白烧电）；条目不设 `Modified`，
于是同一份库导出两次字节相同（有测试）。

### 第 2 步：为什么不现在接线

**接线是故意缓的**，不是漏了。现在唯一能写的地方是应用私有目录，而那个地方**卸载就没了** ——
接上去等于交付一个恰好解决不了这张票核心问题的按钮。

第 2 步的形状（Go 侧几乎不用动）：Go 先把包写进应用私有目录里的临时文件，**成功了才认**，
再由 Java 宿主用 MediaStore 把它拷进「下载」目录。宿主那一跳躲不掉（WebView 与 Go 都碰不到
那个 API），Go 侧只要保证「有一个已经打好的包」就够。若希望 Go 侧直接吐路径，
最省事的增量是加 `WriteBundleTo(path string) (Result, error)`（三行，包在 `WriteBundle` 外面），
但「导出到下载目录」这件事仍然要宿主回话才知道成没成。

**建议与票 12 的宿主补丁一起做**（都是「只能在真机上做的宿主补丁」），一次真机会话里做完。

### 第 2 步的 Go 半边

`Stage() Bundle`：打好包放在**应用私有目录**里，返回它的落点与建议文件名（`错题本-<日期>.zip`）。
停在私有目录是刻意的 —— 搬进系统「下载」目录那一步只能由宿主做（Go 与 WebView 都碰不到
Android 的存储 API），所以这一层只负责「有一个已经打好的包」。

- 「要么一个完整的包、要么什么都不留」照旧：先写临时文件，成功了再改名。半截的 zip 顶着备份的
  名字留在盘上**比没有包更坏** —— 没收尾就没有中央目录，既打不开也认不出它是坏的。
- 每次 Stage 先清掉上一次没搬走的包（拷贝失败、或者用户没给权限），免得越积越多。
- 文件名里的日期走**注入的时钟**，所以可测，也不会在午夜线上抖。
- 宿主搬成功之后**删掉源文件**（它是临时包）；失败则保留，好让用户能重试。

`*export.Service` **没有**直接注册成前端服务：它还有 `WriteBundle(io.Writer)`，而 Wails 要拿
导出的方法生成 TS 绑定 —— 一个 `io.Writer` 形参在 TS 那边没有对应的东西。所以 `main.go` 里加了个
只露 `Stage` 的薄适配（`bundleStager`），与 `cardFiles` 同一个做法（都是绑定边界，不是抽象）。

### 第 2 步的宿主半边（`WailsJSBridge.copyToDownloads`）

**走 `WailsJSBridge` 而不是 `WailsBridge`**：后者那些方法（`share` / `postNotification` / …）是
「Go 经 JNI 调」的，对应的 Go 包装在 Wails 模块里 —— **改不了**。而 `WailsJSBridge` 注册名就是
`window.wails`（`MainActivity.java:244`），它是脚手架文件、归我们，所以在这里加一个
`@JavascriptInterface` 方法，前端就能**直接同步调** Java。（顺带确认过 Wails 自己的 runtime
只**读** `window.wails.invoke` 而不覆盖这个对象，所以不会被顶掉。）

- **MediaStore 而不是直接写 `/sdcard/Download/`**：scoped storage 会拒。用
  `MediaStore.Downloads` + `RELATIVE_PATH=Download` + `IS_PENDING`（写完清掉），
  不需要 `WRITE_EXTERNAL_STORAGE`（也没加那条权限）。拷一半失败会把那个 pending 条目删掉，
  不留 0 字节的坏包。
- **安全校验**：路径必须落在本应用私有目录里（用 `getCanonicalPath()` 比对 —— `..` 与软链都
  已经解开，`files/../../shared_prefs/x.xml` 过不去）。这是个 JS 可调的方法，不该变成一个
  「把任意可读文件拷到下载目录」的工具。
- **成功之后才删源文件**（它已经落进下载目录了，私有目录那份既防不了丢又多占一份空间）；
  任何失败路径都不删，好让用户重试。
- 返回的 `display` 是**回查 `DISPLAY_NAME` 得到的实际名**（重名时 MediaStore 会改名），
  所以界面上说的落点与用户在「文件」App 里看到的一致。
- **同步而不是异步**：包最多几十 MB，MediaStore 写入是本地 IPC，实际零点几秒；异步要把结果
  绕一圈回调和 Go，复杂度远大于它省下的那点卡顿。javadoc 里留了一句「涨到几百 MB 时这里要重新考虑」。

**一个能力缺口（不是忘了）**：**安卓 10 以下不支持** —— 21–28 没有 `MediaStore.Downloads`，
写公共目录要 `WRITE_EXTERNAL_STORAGE`（得再加一条 manifest 权限 + 运行时申请），
而这个方法是同步的、没有「申请完再回来」的地方。宿主返回一句明确的错误而不是静默失败。
要覆盖 <10 就得再补一条权限和一条异步路径。
