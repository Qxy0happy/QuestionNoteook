# 01: 用真实照片验一次打标签质量

**What to build:** 拿几道**真实的印刷体**错题照片走一遍打标签，看 VLM 给出的分层标签到底能不能用。这是一张**验证票** —— 产出是结论与证据，不是产品代码。

> 这张票原先写成「验手写识别」，**前提是错的**（2026-09-16 更正）：错题的**题目是印刷的**，用户拍的是习题册 / 真题上的印刷题面；手写只出现在用户自己的解答上，而那不进 VLM。所用模型的公开跑分本来就是印刷体文档问答 —— 那正是本场景，不是不利条件。
>
> 所以这里要验的**不是「能不能读」**，而是「给的分层标签合不合用、prompt 要怎么调」。

**Blocked by:** None (can start immediately)

**Status:** done（2026-09-16，**用户验的**）—— 结论：**标签大致可用，prompt 保持现状**

- [x] 取至少 3 张真实的**印刷体**错题照片（含公式）走一次打标签
- [x] 记录：标签层级对不对、粒度合不合适、prompt 需要怎么改
- [x] 结论落到 `.scratch/core-loop/` 下的一份文件里，供票据 09 定 prompt 时参考
- [x] 若标签质量不可用，明确给出替代方案 —— **不需要**：质量可用

## Comments

### 证据（我这边能核到的）

- **2026-09-16 真机上拍了 4 张**，我把它们从设备拉下来逐一看过，字节数与设备上逐一相同：
  - 4 张全是**印刷体**（习题册/真题的题面），公式清晰（如 `c = 2 ln(1+b)`、`b_n = Σ k/(a_n+n²)`）；
  - 拉正得很好、没有明显残余透视；
  - 分辨率 2903×470 / 2950×470 这一档 —— **足够**模型读。
- 设备上有 `vlm-files.json`（上传缓存）→ **打标签确实跑成功过**（上传过图、缓存了 file_id）。
- **用户结论（原话）**：「给的标签是差不多正常的」「我大致满意这个功能了」。

### 结论

**打标签的 prompt 保持现状，票据 09 那个「暂定」的标记可以去掉了。**
`internal/vlm/prompt.go` 与 `internal/workload/prompt.go` 里都写着「暂定、待票 01 定稿」——
现在这句可以改成「用户 2026-09-16 用真实印刷题验过，结论是可用」。

### 这份结论的**份量**（照实说）

它是**用户一句"差不多正常"级别的验收**，不是逐层审计。所以下面这些**没有**被验过，
将来真觉得别扭时值得回头查：

- 三层的**层级**是不是都对（比如有没有把"章节"当"知识点"挂）；
- **粒度**合不合这本习题册的组织方式（太细会挂出一堆一次性标签，太粗就失去筛选意义）；
- 它有没有**复用已有的同名标签**而不是每次新建（票 11 的 `SaveTags` 依赖这个行为）；
- 标签**数量**合不合适（现在 prompt 里有条数上限，那个值是按什么定的）。

### 为什么没有我自己再跑一遍

用户说「这个随便你」，但跑一遍要花他的 API 额度、而且要把照片再发出去一次 ——
换来的只是把一句已经够用的结论变细。**不做**。真要细看时，这 4 张图与那次调用
（`internal/vlm` 的 `SuggestTags`）都还在，随时可以重跑。
