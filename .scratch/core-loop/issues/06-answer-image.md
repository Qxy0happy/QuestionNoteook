## Comments

### 补拍怎么走完一趟

详情页新增一行动作（「补拍答案图」/「重拍答案图」+「标签」）。按下之后由 `App.svelte`
记下**是哪道题**并把页面滑到取景页 —— 题库页不知道该怎么做这件事，它只把题交上去。

取景页在补拍态下走的是**同一条**路径：`confirm()` 里判定当前是补拍就把 `AttachAnswer(id, …)`
而不是 `Capture(…)`，两者都落在同一对「拉正 + 按内容 hash 落盘」上，只是补拍多一步
`SetAnswerHash`。**题图与答案图共用一张去重表**，所以同一张图完全可能既是 A 的题图、
又是 B 的答案图（ADR-0004）。

### 状态泄漏：一个只有走完整流程才看得见的坑

`Capture` 只在用户按「完成」时回调，**取消路径不存在** —— 而 Cancel 的方式就是横向滑走。
不在别处清掉的话那道题的 ID 会一直挂着，几十秒后对着另一道题按下快门，答案图就**静默挂到了
之前那道题上**。

处置在 `App.svelte`：补拍态只在取景页停稳的时候算数（滚动停了之后再判当前在哪一页）。
判据放在「停稳后」而不是 `scroll` 事件里，是因为切页用的是平滑滚动，起手那几帧还在题库页上，
边滚边判会把刚设上的补拍态立刻抹掉。

### 换下来的旧答案图会被回收

`AttachAnswer` 返回后 Go 侧会问一句「这个旧 hash 还有别的错题引用吗」，没有才删文件。
重拍过的那张就是在这里才算真的落地 —— 前端不需要知道文件的事。
