# 错题本 · 核心闭环

## Problem Statement

考研备考时，做错的题散在三处：卷子上、手机相册里、脑子里。手抄到错题本上费时，抄完就束之高阁 —— **没有任何机制决定「什么时候该重看哪一道」**。结果是同一类题反复错，而已经会的题又被反复翻。到考前一两个月，错题本已经厚到不敢打开。

## Solution

一个安卓应用，把「拍一道题」当作唯一入口。

拍下**题图**（必填）与**答案图**（可选），在一个可变边长的矩形选区里框出一道题，应用把它透视拉正后入库。云端 VLM 给出分层的语义标签，并且可以就着这道题讨论。FSRS 按复习后的四档**评级**排下一次**到期**时间，每天固定时间汇总提醒。应用内还有一个 agent 能协助整理数据 —— 但它的每一次写入都要用户逐条批准。

5. 作为一个框歪了的人，我想能重拍，这样不用接受一张废图
6. 作为把书页拍横了的人，我想能旋转底图，这样不用歪着框

## Implementation Decisions

### 测试缝

**全应用只有一条测试缝：Go service 层。**

Wails v3 里 `application.NewService(&X{})` 的 `X` 就是一个普通 Go struct，因此测试可以直接 `new` 出 service、调它的方法、断言返回值，**不需要跑起 Wails 应用**。这是可用的最高缝，也是唯一的缝。

前端（预览取景、HUD、手选框手势、三页导航、复习界面）是薄视图，**不做自动化测试**，真机手验。任何落到前端的逻辑都是缝外的东西 —— 所以逻辑刻意不往前端放（见下面的图像处理契约）。

**一处有边界的例外（2026-09-16 补）**：**不含任何外部依赖的纯函数**可以直接单测，不另算一道缝 —— 这条「只有一条缝」针对的是**集成点**（谁和谁接、在哪儿断言行为），不是禁止测一个纯函数。目前只有一处：`main_test.go` 测 `packageFromCmdline`（解析 `/proc/self/cmdline` 取包名的那段），因为安卓那条分支在桌面上**永远跑不到**，不把它拆成纯函数就只能靠真机验。

**新增这类例外时要在票或提交里写明理由**，别让它悄悄长成一堆「顺手加的测试」。

### 服务划分

所有服务都注册进 `Services`，构成那一条缝。

- **采集（Capture）** —— 接收一张原图与四个角点，做透视重映射，把结果落成一张题图，返回新**错题**的标识。**答案图与题图走同一条路径**，只是落点不同。
- **题库（Library）** —— 错题的新增、删除、查询；按标签筛选、关键词搜索；读取题图/答案图。
- **标签（Tags）** —— 三层标签的增删改；顶层学科由用户自由填写，仅预置考研四门作为初始值；标签词表的读写。
- **复习（Review）** —— 取今日**复习队列**；记录一次复习（四档评级）；把评级交给 FSRS 算出下一次**到期**。
- **讨论（Discussion）** —— 就某道错题与 VLM 对话；串是「预设追问 + 可继续自由聊」；记录**挂在错题上**，可回看。
- **VLM 客户端（VLMClient）** —— 对云端多模态服务的抽象。
- **待批准（Pending）** —— 记录 agent 提议的、尚未生效的改动；逐条批准或丢弃。
- **Agent** —— 把 VLM 的 tool-calling 接到上面这些服务上。**它读得到一切，但所有写操作都必须经由待批准层。**
- **导出（Export）** —— 打包 zip。
- **通知（Notify）** —— 每天固定时间发一条汇总。

### 图像处理契约（缝内）

- 输入：**原图**（内存中的位图）+ **四个角点**（图像像素坐标，由前端从手势换算而来）
- 输出：透视拉正后的**题图**
- **不做自动检测**：不找纸面四角、不识别文本块、不切题。四个角点完全来自用户拖动（ADR-0006）
- **原图即弃**：题图落盘后原图不再保留（ADR-0007）。因此**确认框选那一刻定稿**，框歪了只能重拍
- 不做不可逆增强：存原始像素

### 存储

- 元数据在 SQLite；图片体积大，**存在库外**，按**内容 hash** 命名（ADR-0004）
- 内容 hash 带来天然去重：同一道题拍两次只存一份
- 沙箱内存储 —— 安卓上目录对话框不可用，所有落点都在应用私有目录
- 主要实体：
  - **错题** —— 持有题图 hash、答案图 hash（可空）、创建时间
  - **标签** —— 自引用树（父 → 子），带层级
  - **错题-标签** 关联
  - **复习状态** —— 每道错题一份 FSRS 状态（到期、稳定度、难度、已复习次数、失误次数、状态机阶段、上次复习时间）
  - **复习记录** —— 每次复习一条（评级、时间、当时算出的下次间隔）
  - **讨论** —— 挂在错题上
  - **待批准改动** —— 类型 + 载荷 + 状态

### FSRS

- 用官方 `github.com/open-spaced-repetition/go-fsrs/v4 @ v4.0.0`，即 **FSRS-6**（21 元素权重）
- **跑在 Go 侧**，不跑前端（ADR-0002）
- 用**官方默认权重**。个人错题本量小，自训练参数不现实
- 评级是它唯一的评分输入，四档直接对应
- 「每日复习量由 VLM 推荐」是**在 FSRS 之上再加一道闸**：FSRS 用 `RequestRetention` 控制到期量，VLM 那层回答「今天最多做几道」。它要能看到「今日到期多少」与「最近的表现」

### VLM

- 云端，**国内可直连**，**OpenAI 兼容端点**（ADR-0005）。所选视觉模型带 `Exp` 后缀、官方声明可能被替换，因此：
  - **provider 抽象不是可选项**：base_url 与模型名从配置来，**不得硬编码模型 ID**
  - 保留纯文本模型作为非图片流量的回落
- 三类用途：
  1. **打语义标签** —— 主动触发，不自动。返回的标签先给用户编辑，保存才生效
  2. **就题讨论** —— 预设追问为入口，之后可自由聊
  3. **Agent 管理数据** —— tool-calling，写操作全部转成待批准改动
- 图片输入方式：原图可能不小，优先用服务方的文件/引用接口避免重复上传；**图片只能放在 user 消息里**（该服务商的硬约束）
- 解析密集文档时要显式指定高保真模式，否则会被降采样

### 待批准层

- agent 提议的每次改动生成**一条**待批准记录（不是攒一批）
- 用户逐条批准或丢弃；**批准前不影响正式数据**
- 这一层顺带给出 undo：丢弃一条待批准记录即可

### 导出

- **zip 包**：SQLite 库 + 图片目录（ADR-0004）
- 不做分享功能
- 沙箱意味着卸载即全没，导出是防丢的唯一手段

### 通知

- **每天固定时间汇总一次**，形如「今天有 N 道待复习」
- 不发单题通知
- 当天没有到期题则不发

### 界面骨架

- 主界面**三页**：左 Agent / 中 **拍照（默认落地页）** / 右 题库
- 题库页 = 列表 + 标签筛选 + 关键词搜索
- 取景页：固定居中圆角矩形 + 中心十字（**没有实时边缘检测**）
- 按下快门后：底图铺满 + 居中默认尺寸的可变边长矩形选框 + 重拍/确认/旋转

## Testing Decisions

全新仓库，**没有既有测试可作为先例** —— 这是第一份。

**什么算好测试**：只测外部行为，不测实现细节。具体到本项目：调用 service 的方法、断言它返回的东西与它落盘/落库的结果，不断言内部调了谁几次。

**测哪些**：

- **采集** —— 喂一张合成的、已知四角的图（比如程序画出的、带明显畸变的棋盘格），断言拉正后的题图在预期位置有预期像素。这是唯一需要 fixture 图的地方；fixture 应当**在测试里程序生成**而不是提交二进制
- **复习** —— 同一道题连喂四次不同评级，断言算出的下次到期时间符合 FSRS 的单调性（Good 应比 Again 推得远）；断言复习记录被写下
- **标签** —— 三层树的增删改；删一个中间节点时其子节点怎么办
- **待批准** —— 提议一条改动后，正式数据**不变**；批准后才变；丢弃后不变
- **题库** —— 按标签筛选与关键词搜索的边界（无标签的题、标签被删掉的题）
- **导出** —— 导出的 zip 里，库里引用的每个图片文件都在；反过来，zip 里不该有库没引用的孤儿
- **Agent 的写路径** —— 断言 agent 的每次写都**必然**产生一条待批准记录，即「没有绕过待批准层直接改数据的路径」。这是安全属性，值得一个专门的测试

**不测**：前端的一切（视图层）、UI 手势、通知的实际投递、VLM 网络调用本身（测我们那侧的处理，用假的 provider 实现）。

## Out of Scope

- **自动题块检测、版面分析、切题**，以及任何为此服务的端侧模型（NPU / ONNX）—— 见 ADR-0006
- **云同步、账号、多设备** —— 先自用，不做后端
- **分享到其他 app** —— 导出走整库 zip，不做单题分享
- **iOS 与桌面平台** —— 目标只有安卓（脚手架里的 iOS/桌面目录留着但不维护）
- **保留原图、事后重新裁剪** —— 确认框选即定稿，见 ADR-0007
- **由 VLM 生成答案** —— 用户选择另外拍摄答案图
- **程序判题** —— 评级完全来自用户自评
- **图片增强** —— 存原始像素，不做背景归一化 / CLAHE / 锐化

### 脚手架补丁

对 Wails 脚手架的改动分散在两处，**升级 Wails 或重新 init 都会覆盖它们**，理由已写在各自的文件注释里：

- `build/android/Taskfile.yml` —— Windows 宿主分支、`sort -V` 静默失败、`gradlew.bat`、`-x` 判据、反斜杠路径、去掉 `awk` 依赖；外加 `assemble:apk:release` 上的 `GRADLE_ARGS` 透传（发 Release 时注版本名用，理由写在那个 var 的注释里）
- `build/android/build.gradle` + Gradle wrapper —— AGP 9.2.0、Gradle 9.7.1、腾讯云镜像
- `build/android/app/build.gradle` + `strings.xml` —— 应用身份（applicationId 与显示名）；外加 `versionName` 改成可由 `-PversionName` 注入（本地构建无此参数时仍是 `"1.0"`，`versionCode` 刻意不动）；以及**签名**：改成读 `keystore/keystore.properties`，并去掉脚手架那个「没钥匙就退回 debug keystore」的兜底（钥匙不在就构建失败，而不是发一个以后装不回来的包）
- `build/android/keystore/` —— **我们自己加的**（不是脚手架产物，re-init 不会把它加回来）：发版的签名钥匙（`questionbook-release.p12`）与口令（`keystore.properties`），明文。**这把钥匙不能换**，理由写在那份 properties 顶部
- `build/android/app/src/main/java/com/wails/app/MainActivity.java` —— **补 `WebChromeClient`**。出厂脚手架整个包里一个都没有，于是 `getUserMedia` 一律被拒；另外补了 console → logcat 的转发
- `build/ios/app_options_default.go` —— **删除**。它的 `!ios` 标签会让其它平台的 `go build ./...` 失败（详见该次提交）
